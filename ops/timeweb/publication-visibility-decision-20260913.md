## Какое решение требуется

Для продолжения в тех же двух пакетах предлагается **явно разрешить публичные
технические образы этого уже публичного проекта**. Это изменение прежнего
требования `private`, поэтому оно не применено автоматически.

Если владелец выбирает этот вариант, разрешение должно охватывать только:

1. Публичные пакеты `san4o9910/kinetra-backend` и `san4o9910/kinetra-frontend`,
   принадлежащие `San4o9910/Kinetra`, для приложения
   `73b665065e00a5b375e90f701373b3e0856a0386`.
2. Замену ожидаемой видимости `private` на явно согласованную `public` в проверках
   публикации и дальнейшей проверки происхождения образов, с точными именами
   пакетов, владельцем и привязкой к репозиторию. Условие не просто удаляется.
3. Новую полную успешную проверку и только затем запуск по существующим
   database → application → HTTPS этапам. Неуспешный run `34733519897` не
   переименовывается в успешный и сам по себе не даёт права запуска.

Не меняются код приложения, исходный SBOM, два согласованных CPE-исключения и
срок их действия, остальные проверки, закрытость серверных секретов и базы,
ограничения на оплату, сообщения, удаление данных и merge. Новые фактические
digests после повторной сборки берутся только из её успешно проверенных результатов.

Альтернатива — сохранить требование закрытых образов. Тогда нужен отдельный
согласованный план публикации в заранее подтверждённые private-пакеты и
соответствующей смены точных привязок. Уже публичный пакет нельзя просто
переключить обратно в private: это прямо указано в
[документации GitHub](https://docs.github.com/en/packages/learn-github-packages/configuring-a-packages-access-control-and-visibility#configuring-visibility-of-packages-for-your-personal-account).
Удалять существующие пакеты или менять замороженные привязки без отдельного
разрешения нельзя. Создание новых имён само по себе ещё не доказывает закрытость.

Почему опубликованные пакеты получили public вопреки документированному private
по умолчанию, по доступным данным не установлено. Workflow не выполнял команд
изменения видимости. Повторять публикацию вслепую или отменять проверку нельзя.

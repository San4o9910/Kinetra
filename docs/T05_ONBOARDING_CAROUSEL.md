# T05 — Онбординг-карусель

## UX и точный текст

Карусель состоит из шести слайдов. Текст является частью продуктовой спецификации и должен отображаться без перефразирования:

1. **Добро пожаловать в Kinetra**

   Это не просто тренировки. Это образ жизни, который делает вас сильнее, гибче и энергичнее

2. **Активность не тратит энергию. Она её создаёт**

   Каждое занятие — это вклад в вашу бодрость, ясность ума и уверенность в себе. Вы почувствуете разницу уже через 2 недели

3. **7 ритмов недели**

   | День | Ритм            |
   | ---- | --------------- |
   | Пн   | Дыхание         |
   | Вт   | Сила            |
   | Ср   | Тело мой дом    |
   | Чт   | Функционал      |
   | Пт   | Растяжка        |
   | Сб   | Нейрогимнастика |
   | Вс   | Питание         |

4. **Изучите базу**

   Мы научим вас 7 базовым движениям, которые лежат в основе любых тренировок. Это убережёт от травм и сделает каждое упражнение осмысленным

5. **Вы сможете двигаться свободно и без боли**

   Подниматься по лестнице без одышки, носить сумки без напряжения в спине, играть с детьми и не бояться падений. Это и есть настоящая сила

6. **Готовы начать?**

Пользователь перемещается кнопками `Назад` и `Далее`, индикаторами слайдов, клавишами `←`/`→`, `Home`/`End` или горизонтальным свайпом. На последнем слайде кнопка `К базовым урокам` завершает онбординг. Выход за границы первого и последнего слайда невозможен.

## Маршрутизация и сохранение прогресса

Серверный `onboardingStatus` остаётся источником истины для маршрута:

- `onboarding_pending` → `/onboarding`;
- `base_lessons` → `/base-lessons`.

Текущий индекс слайда хранится в `sessionStorage` под ключом `kinetra.onboarding.slide`, поэтому восстанавливается после перезагрузки вкладки. Сопутствующий ключ `kinetra.onboarding.user` привязывает прогресс к текущему пользователю: другой аккаунт в той же вкладке начинает с первого слайда. Некорректное или выходящее за диапазон значение безопасно сбрасывается на первый слайд. После успешного завершения онбординга оба ключа удаляются. Отказ или недоступность `sessionStorage` не блокируют карусель; токены и другие секреты в этом хранилище не сохраняются.

Свайп поддерживает touch, pen и основную кнопку мыши через Pointer Events. Смена слайда происходит только после горизонтального движения не менее 48 px; вертикальный жест остаётся прокруткой страницы. Пограничные жесты получают визуальное сопротивление, но не меняют индекс.

## Доступность и адаптивность

- Карусель имеет доступное имя, описание текущей позиции и `aria-live`-уведомление при смене слайда.
- Неактивные слайды скрыты от accessibility tree; точки навигации и кнопки имеют содержательные `aria-label`.
- Все интерактивные цели имеют размер не менее 44 × 44 px и доступны с клавиатуры.
- Во время API-запроса повторное завершение блокируется, а ошибка показывается рядом с CTA и допускает повторную попытку. Истёкшая refresh-сессия возвращает пользователя на экран входа без ложного authenticated-состояния.
- `prefers-reduced-motion: reduce` отключает значимые переходы.
- Вёрстка поддерживает ширину 320–428 px без горизонтального переполнения, использует safe-area inset для устройств с вырезами и остаётся пригодной для больших экранов.
- Визуальные токены соответствуют теме Kinetra: фон `#080909`, карточки `#181C1C`, акцент `#C8F169`, основной текст `#F4F6F2`, шрифт Inter.

## Защищённый API

### `PUT /api/v1/me/onboarding-complete`

Endpoint требует access JWT в заголовке `Authorization: Bearer <token>` и возвращает обновлённый профиль с HTTP `200`. Тело запроса не требуется. Идентификатор пользователя берётся исключительно из проверенного JWT subject; переданный клиентом `userId` не может выбрать или изменить чужой профиль.

Репозиторий выполняет операцию в транзакции PostgreSQL и блокирует строку пользователя через `SELECT ... FOR UPDATE`. Разрешён только монотонный переход `onboarding_pending` → `base_lessons`. Повторный запрос идемпотентен, а статусы `survey_pending`, `base_lessons` и `active` не переводятся назад или вперёд этим endpoint.

## Приёмка и тестирование

Из корня репозитория выполняются стандартные проверки:

```bash
npm run verify:structure
npm run typecheck
npm run lint
npm run test
npm run build
```

Покрытие T05 включает:

- backend E2E: обязательный JWT, игнорирование `userId` из тела, разрешённый переход, идемпотентный повтор и сохранение остальных статусов;
- PostgreSQL integration test: реальный транзакционный переход и повторное завершение при заданном `DATABASE_URL`;
- frontend unit tests: точный текст, семь ритмов, восстановление индекса и правила свайпа;
- API client test: аутентифицированный `PUT` без тела;
- browser E2E: переход `survey → onboarding`, кнопки, точки, клавиатура, нативный touch/mouse swipe, восстановление после reload, адаптивность 320 и 428 px, истёкшая refresh-сессия с повторным входом, ошибка с повтором, завершение, переход к базовым урокам и logout.

Успешная browser-проверка печатает маркер `KINETRA_T05_BROWSER_E2E=PASS`, а PostgreSQL-проверка — `KINETRA_T05_POSTGRES_INTEGRATION=PASS`. Маркеры T04 сохраняются, чтобы T05 не ослаблял уже принятую функциональность.

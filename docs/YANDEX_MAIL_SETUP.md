# Яндекс Почта для Kinetra

Для небольшого первого запуска выбран существующий ящик Яндекса. Он будет
отправителем писем восстановления пароля и, если эта функция включена, подтверждения
email. Оплата в Kinetra остаётся выключенной.

## Что нужно от владельца

1. В [Яндекс Почте](https://mail.yandex.ru/) откройте **Настройки → Почтовые программы**.
   Включите доступ по IMAP и вариант **Пароли приложений и OAuth-токены**, сохраните.
   Яндекс указывает эти настройки и для подключения только отправки писем.
2. Откройте [Пароли приложений](https://id.yandex.ru/security/app-passwords), выберите
   **Почта**, назовите пароль `Kinetra SMTP` и сохраните показанный пароль.
   По текущей инструкции Яндекса он начинает действовать через **2–3 часа** и
   показывается только один раз.
3. В [Secrets репозитория](https://github.com/San4o9910/Kinetra/settings/secrets/actions)
   добавьте два repository secret:

| Name                                | Secret                              |
| ----------------------------------- | ----------------------------------- |
| `AUTH_TOKEN_DELIVERY_SMTP_USERNAME` | Полный адрес выбранного ящика       |
| `AUTH_TOKEN_DELIVERY_SMTP_PASSWORD` | Созданный пароль приложения «Почта» |

Основной пароль Яндекса для этого подключения не используется. Не размещайте пароль
приложения в переписке, README, коммитах или скриншотах. Для отдельной программы используйте
отдельный пароль приложения. Инструкция Яндекса: [подключение SMTP](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others),
[создание пароля приложения](https://yandex.ru/support/id/ru/authorization/app-passwords).

## Настройки приложения

Их задаёт сценарий подготовки сервера; владельцу достаточно двух секретов выше.

```dotenv
AUTH_TOKEN_DELIVERY_MODE=smtp
AUTH_TOKEN_DELIVERY_SMTP_SERVICE=yandex
AUTH_TOKEN_DELIVERY_SMTP_USERNAME=<sender-email>
AUTH_TOKEN_DELIVERY_SMTP_PASSWORD=<mail-app-password>
AUTH_TOKEN_DELIVERY_APP_ORIGIN=https://80.68.156.131
AUTH_TOKEN_DELIVERY_TIMEOUT_MS=10000
AUTH_TOKEN_DELIVERY_WEBHOOK_URL=
AUTH_TOKEN_DELIVERY_WEBHOOK_SECRET=
```

Origin должен в точности присутствовать в `CORS_ORIGIN`. SMTP соединяется с
`smtp.yandex.ru:465` по TLS с проверкой сертификата; адрес отправителя совпадает
с выбранным ящиком. В приложении также поддержан сервис `gmail`, но автоматического
переключения или повторной отправки через другой сервис нет. Данные SMTP получает
только API, без передачи в отдельные workers.

Пароль принимается без обрезания или изменения: 16–256 печатных ASCII символов без
пробелов. Серверные файлы окружения дополнительно сохраняют существующий запрет
на `$`, кавычки и обратные кавычки; обычные сгенерированные пароли Яндекс/Gmail
укладываются в эти ограничения.

## Сеть Timeweb и проверка

Timeweb сообщает, что у новых облачных серверов порт **465 блокируется по умолчанию**.
Его доступность на конкретном сервере должна быть проверена отдельно. Снять блокировку
можно в панели управления; если такой возможности нет, Timeweb направляет в поддержку.
Это не исправляется сменой порта в коде приложения.
[Официальные ограничения Timeweb](https://timeweb.cloud/docs/cloud-servers/limitations).

Кодовые тесты используют синтетические данные и не отправляют писем. Реальные SMTP
credentials, сетевое подключение, принятие письма провайдером и получение его в ящик —
отдельные проверки. Успешная аутентификация SMTP сама по себе не доказывает доставку.
Реальные сообщения в текущем разрешении владельца исключены; тестовое письмо требует
указания получателя и отдельного разрешения.
